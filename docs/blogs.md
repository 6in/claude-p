# 💸 Claude Max なのに「-p」で課金される…を、curl で全部解決するツールを作りました

こんにちは！ 👋

Claude Max を契約しているのに、シェルスクリプトや自動化ループから Claude を呼ぼうとすると、`claude -p` だと API クレジット課金が発生しちゃう……サブスクの中で完結させたいですよね 😢。かといって対話型 TUI を `expect` で叩くのはなかなか脆いんです。

そこで！ `ht-mcp`（headless terminal MCP）越しに Claude Code を駆動して、**`curl` 1 発でタスク投入と結果取得が完結する**薄い HTTP WebIF を Rust で作ってみました ✨ 名前は **claude-p** です。

## 😩 ① なぜ作ったか — `claude -p` を避けたい

Claude Max を契約済みなら、できれば API 経由ではなくサブスク枠で Claude を回したいですよね。でも `claude -p` は便利な反面、**API クレジットで別請求**になってしまうんです 💳💦 サブスクとは別の財布から出ていく構造……ちょっと切ない。料金体系の最近の変更については [Claude の料金体系まわりの整理（@sakamoto66）](https://qiita.com/sakamoto66/items/abe1f1106104a9bd1b34) がとても分かりやすいので、こちらもぜひ。

代替手段として対話型 TUI を `tmux` + `expect` で叩く方式も思いつくんですが、PTY 制御は脆くて、画面崩れや入力タイミングで詰まりがちなんですよね 😵‍💫

そんなときにふと思いついたんです。「**Claude Code を起動したターミナルを自動操作して、そこにプロンプトを流し込めばいいのでは？**」💡 普段わたしたちが対話で使っているあの画面に、人間の代わりにプログラムが入力してくれれば、サブスク経由のまま Claude を呼び出せるはずです。

そこから「ターミナルをプログラムから操作する」方法を探していくうちに、**`ht-mcp`** にたどり着きました 🎯 Headless Terminal を MCP サーバとして叩ける仕組みで、これさえあれば対話型の Claude Code TUI を「裏で」自動操作できます。

あとは ht-mcp を叩くための薄い **Web インタフェース** を Rust で被せるだけ。curl 1 発で Claude にタスクを投げて結果が返ってくる、というシンプルな仕組みのできあがりです ✨

## 📨 ② claude-p がやること

HTTP POST でプロンプトを投げる → JSON で結果が返る。本当にそれだけのツールです 😊

- 💰 課金経路は **Max サブスクの OAuth (`~/.claude/.credentials.json`)** だけ
- 🚫 `ANTHROPIC_API_KEY` は使いません ／ `claude -p` も呼びません
- 🔁 ターンは直列処理（同時 1 件）、`turns/` ディレクトリにすべての入出力が残ります

「Claude が走り終わったら結果がファイルに落ちてるはずなので拾いに行く」というファイル駆動の素朴さなので、リトライも追跡もすごく楽になります 🗂️✨

## 🏗️ ③ アーキテクチャ — `ht-mcp` で対話型 TUI を駆動する

### 🤔 そもそも「Headless Terminal」って？

ひと言でいうと、**画面（ディスプレイ）を持たない仮想ターミナル**のことです 🖥️→👻

普段わたしたちが使っているターミナル（iTerm、Windows Terminal、GNOME Terminal など）は「人間に画面を見せる」のが仕事です。一方、**Headless Terminal（ht）** は同じ仮想端末（PTY）の機能を、**プログラムから操作するため**だけに切り出したものなんです 🧰

つまり、

- 👀 人間が見る代わりに → プログラムが「画面の状態」を文字列として取り出せる
- ⌨️ 人間がキーボードを叩く代わりに → プログラムが任意のキー入力を流し込める

`ht-mcp` は、その Headless Terminal の機能を **MCP（Model Context Protocol）サーバ** として公開してくれるツールです 📡 これがあるおかげで、ht-webif は「対話型の claude TUI を、まるで人間が触っているかのように」スクリプトから操作できる、というわけなんです ✨

### 🗺️ 全体のデータフロー

データフローはこんな感じです 👇

```
[curl] ─HTTP─▶ WebIF (axum) ─MCP(stdio)─▶ ht-mcp ─PTY─▶ claude TUI
                  │                                       │
                  ▼                                       ▼
              turns/ ◀──── prompt / result / status ファイル
```

- 🦀 **WebIF (axum)** が HTTP を受けてターン ID を発番して、`turns/prompt-<id>.txt` を書きます
- 🖥️ **ht-mcp** は stdio MCP サーバで、claude TUI を子プロセスとして PTY で抱えてくれます
- 🤖 **claude TUI** は普段ユーザが対話で使っているもの。今回はプロンプト末尾に「出力規約」を付け足して、`result-<id>.txt` と `status-<id>.json` を書き出してもらいます
- 🏁 **status ファイルの出現 = 完了シグナル**。インメモリでジョブ管理せず、ファイルシステムを唯一の真実として扱う設計です

もし TUI が wedge（応答不能）になっても、`ht-mcp` ごと再起動して新しいセッションを立てる **shared-fate recovery** を組み込んであります 🔄 WebIF 本体はそのまま生き続けるので、curl から見れば数百ミリ秒のラグで透過的に復旧します 💪

## 📦 ④ 前提：先に揃えておくもの

使い始める前に、3 つだけ準備が必要です 🛠️

- 🦀 **Rust toolchain**（edition 2021 対応の stable Rust）— `rustup` でサクッと入ります
- 🖥️ **`ht-mcp` バイナリ** — 別途インストールして PATH に通すか、`HT_MCP_PATH` 環境変数でパスを指定してください（例: `~/.cargo/bin/ht-mcp`）。**これが今回いちばん大事な前提**で、ht-webif は ht-mcp が動いてはじめて Claude を駆動できます ✨
- 🔑 **`claude` CLI**（Max サブスクで**ログイン済み**であること） — `~/.claude/.credentials.json` の OAuth に乗っかる仕組みなので、`ANTHROPIC_API_KEY` は不要です

ここさえクリアしておけば、あとは claude-p を起動して curl で叩くだけです 🙌

## 🎬 ⑤ 使い方 — `curl` 1 発

最小例はこんな感じです 👇

```bash
curl -s -X POST http://127.0.0.1:8080/prompt \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "Rust とは何か 100 字で教えて", "wait": true}'
```

```json
{ "turn_id": "20260527-...", "status": "completed", "result": "Rust は ..." }
```

`wait` を省けば非同期投入になるので、`GET /turns/{turn_id}` でポーリングする使い方もできます 📡 さらに `fresh: true` を渡すと、実行前に `/clear` 相当が走って TUI 文脈をリセットしてからステートレスに 1 発実行できます（これが実質 `-p` の代替ですね 🪄）。

curl すら書きたくない！という方には、同梱の `scripts/claude-p` がおすすめです。`./scripts/claude-p 8080 "..."` の 1 行で投入から結果取得まで終わります。サーバが落ちていれば自動でデーモン化して起動してくれるので、起動忘れの心配もなしです 🌱

## ⚠️ ⑥ つまずきポイントと割り切り

v0.1 段階での主な制約はこちらです 📝

- 🚦 **同時 1 ターン直列処理** — 1 プロセスにつき claude TUI は 1 つです。並列化したい場合は WebIF 自体を多重起動してください（`PORT` と `TURNS_DIR` を分ければ同一ホストで共存できます）
- 🔒 **ループバック専用・認証なし** — `127.0.0.1` バインドです（ポートは `PORT` 環境変数で変更可、既定 `8080`）。外から叩くなら SSH トンネルやリバースプロキシで前段を立ててください
- 🖥️ **シングルホスト前提** — WebIF / ht-mcp / claude が同じファイルシステム上でターン成果物ディレクトリ（既定 `./turns`、`TURNS_DIR` 環境変数で変更可）を共有します
- ⏱️ **タイムアウト**: MCP 30 秒 / 1 ターン 300 秒 / `wait:true` は最大 700 秒

万が一 TUI が固まっても `POST /restart` で丸ごと立て直せるので、長時間運用でも自己回復してくれます 🛠️✨

## 🎁 ⑦ まとめ

- 💸 **サブスクを維持したまま**、curl でプログラマブルに Claude を呼べます
- 🤝 対話型 TUI を切り離すのではなく、**対話のまま叩く**のがミソです
- 🦀 Rust + axum + tokio で単一バイナリ、ファイルシステム = 状態というシンプル構成
- 🎯 自動化ループや cron から Claude を回したいけど `-p` 課金は避けたい、そんな方に刺さるはずです

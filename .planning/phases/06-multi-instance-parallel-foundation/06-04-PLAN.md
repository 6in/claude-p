<objective>
phase 6 UAT Test 2 で確定したギャップを閉じる: 同一インスタンスへ同一ミリ秒に並行 POST /prompt すると turnId(YYYYMMDD-HHMMSS-mmm) が衝突し、prompt/result/status ファイルが互いに上書きされ、GET /turns/{id} が誤った結果を返して 1 ターン分の出力が静かに消失する。

根本原因(確定): src/http.rs:92 の prompt_handler が turnId を `chrono::Utc::now().format("%Y%m%d-%H%M%S-%3f")` のみで採番し一意性ガードを持たない。直列 worker モデル(HT-PROTOCOL §12)は実行を直列化するが、採番は HTTP ハンドラ着信時に並行で行われるため衝突は enqueue 時点で確定する。HT-PROTOCOL §3.2 が要求する「衝突時の連番 -<seq> 付与による一意性のコード保証」が未実装。

Output: src/http.rs に TurnIdAllocator + 並行採番一意性テスト、src/main.rs に配線。

  <action>
HT-PROTOCOL §3.2 が要求する「衝突時の -<seq> 連番付与による一意性のコード保証」を、AppState 所有の単一直列化点として実装する。

(1) 新しい pub struct TurnIdAllocator を src/http.rs に追加する。内部状態は「直前に発番した base タイムスタンプ文字列(YYYYMMDD-HHMMSS-mmm)」と「その base に対して既に払い出した seq カウンタ(u32)」の2フィールドを保持する。この2フィールドは結合した不変条件(同一 base なら seq を単調増加、新しい base なら seq をリセット)を持つため、`tokio::sync::Mutex<TurnIdAllocatorState>` で単一直列化点として保護する。理由をコメントで明記すること: 「base と seq は結合した状態で、新 base 検出時に seq をリセットし同一 base では seq を単調増加させる必要がある。AtomicU64 単体ではこの2フィールド結合不変条件を CAS なしに表現できないため、極短時間だけ保持する tokio::sync::Mutex を採番の単一直列化点とする。std::sync::Mutex ではなく tokio::sync::Mutex を選ぶのは、本クレートの async/lock 慣習(CLAUDE.md)に従い、将来 await を跨ぐ可能性に備えるため。ただし本実装ではロックはメモリ内文字列整形のみで保持し、ファイル I/O や他の .await を跨いで保持しない(worker Mutex とは完全に別ロックであり CR-01 の worker-Mutex 競合を再導入しない)」。

(2) `pub async fn next_turn_id(&self) -> String` を実装する。挙動: ロック取得 → `chrono::Utc::now().format("%Y%m%d-%H%M%S-%3f").to_string()` で base を生成 → ロック内の last_base と比較。base が last_base と異なれば last_base を更新し seq を 0 にリセットして base をそのまま返す(サフィックス無し = 既存形式と後方互換)。base が last_base と一致すれば seq を 1 加算し `format!("{base}-{seq:03}")` を返す(例 `20260615-090456-080-001`)。サフィックスは 3 桁ゼロ埋めの数値のみとし、ハイフンと数字だけで構成する(http.rs:152 の `c.is_ascii_digit() || c == '-'` ホワイトリストを満たす。`-w<workerId>` のような英字形式は使用しない)。ロックはこの整形処理の間だけ保持し、await(ファイル I/O 等)を跨がない。

(3) `TurnIdAllocator::new()` を追加する(初期状態: last_base 空文字、seq 0)。

(4) AppState に `pub turn_id_alloc: Arc<TurnIdAllocator>` フィールドを追加する。フィールドの doc コメントで「turnId 採番の単一直列化点。worker Mutex とは別ロックで、prompt_handler が並行着信しても同一 turnId を採番しない(HT-PROTOCOL §3.2)」と説明する。

(5) prompt_handler(現 src/http.rs:92)の `let turn_id = chrono::Utc::now().format(...).to_string();` を `let turn_id = state.turn_id_alloc.next_turn_id().await;` に置換する。採番箇所のコメントを「turnId 発番(HT-PROTOCOL §3.2: ミリ秒精度 + 衝突時 -<seq> 連番、AppState 所有アロケータで原子化)」へ更新する。prompt_handler は引き続き worker Mutex を取得しない(CR-01 維持)。

(6) src/http.rs の tests モジュール内 build_test_state ヘルパーを更新し、AppState 構築時に `turn_id_alloc: Arc::new(TurnIdAllocator::new())` を渡す(既存テストがコンパイル・グリーンを維持するため)。

## Naming Scheme (LOCKED)

クロスビルド系レシピは `dist-` プレフィクスで namespace する。dev レシピ (`build`, `run`, `test`,
`fmt`, `clippy`, `clean`) と視覚的に区別するため。just は recipe-name に `-` を含められる。

| 旧 Makefile recipe | 新 justfile recipe |
|--------------------|-------------------|
| `help`             | (justfile の default に統合、既存 default 動作 `just --list` を活用) |
| `check-tools`      | `dist-check-tools` |
| `linux-amd64`      | `dist-linux-amd64` |
| `linux-arm64`      | `dist-linux-arm64` |
| `windows-amd64`    | `dist-windows-amd64` |
| `all`              | `dist-all` |
| `clean-dist`       | `dist-clean` |

just のデフォルト挙動は引数なしで `just --list` 相当のレシピ一覧表示 (recipe を 1 つ目に
`default` を置けばオーバライド可能だが、ここでは標準動作のままにする — 既存 justfile も
default を置いていないため統一)。Makefile 側にあった `help` テキスト本文 (使い方説明と
注記) は失わないように、justfile 冒頭のヘッダコメントに統合する。

     - 既存 6 レシピ (`build`, `run`, `test`, `fmt`, `clippy`, `clean`) はそのまま維持。
       各レシピの doc コメント (`# ...`) も既存スタイル踏襲。

  2. just の変数定義をファイル冒頭の `# 変数定義` セクションに追加 (just は `name := value`
     構文をサポート):
     - `cargo_manifest := "Cargo.toml"`
     - `bin_name := "ht-webif"`
     - `dist_dir := "dist"`
     - `cross_cmd := "cross"`
     - `triple_linux_amd64 := "x86_64-unknown-linux-gnu"`
     - `triple_linux_arm64 := "aarch64-unknown-linux-gnu"`
     - `triple_windows_amd64 := "x86_64-pc-windows-gnu"`

  3. 7 つの cross-release レシピを追加 (順序は既存 dev レシピの後):

     - `dist-check-tools`: docker と cross の存在を fail-fast チェック。Makefile の
       `check-tools` の shell ロジック (`command -v ... || { echo ...; exit 1; }`) を
       そのまま移植。レシピ内の各行は indented shell として実行される。最後に `echo "OK: ..."`。

     - `dist-linux-amd64`: 依存に `dist-check-tools` を置き (just の依存構文
       `dist-linux-amd64: dist-check-tools`)、shell 行で
         `mkdir -p {{dist_dir}}`
         `{{cross_cmd}} build --release --target {{triple_linux_amd64}} --manifest-path {{cargo_manifest}}`
         `cp target/{{triple_linux_amd64}}/release/{{bin_name}} {{dist_dir}}/{{bin_name}}-linux-amd64`
         `@echo "built: {{dist_dir}}/{{bin_name}}-linux-amd64"`
       を実行。just の変数展開は `{{var}}` 構文。

     - `dist-linux-arm64`: 同様。triple は `triple_linux_arm64`、出力名は
       `{{bin_name}}-linux-arm64`。

     - `dist-windows-amd64`: 同様。triple は `triple_windows_amd64`、cross 出力は
       `target/{{triple_windows_amd64}}/release/{{bin_name}}.exe`、stage 先は
       `{{dist_dir}}/{{bin_name}}-windows-amd64.exe`。

     - `dist-all`: 依存に 3 つの cross target を並べる
       (`dist-all: dist-linux-amd64 dist-linux-arm64 dist-windows-amd64`)。
       just の依存は順序通り 1 回ずつ実行される。本体に
       `@echo ""` と `@echo "完了: 3 つの cross-stable target を生成しました"` および
       `@echo "  macOS (amd64/arm64) と windows-arm64 は .github/workflows/release.yml で生成されます"`。

     - `dist-clean`: 本体に `rm -rf {{dist_dir}}` と
       `@echo "removed: {{dist_dir}}/"`。

  4. 各 cross-release レシピの直前に `# ` で始まる Japanese doc コメント 1 行を入れる
     (既存 dev レシピと同じスタイル、CLAUDE.md の「Language for Comments and Logs」遵守)。例:
       - `# docker と cross の存在を fail-fast チェック`
       - `# Linux x86_64 バイナリ生成 (cross + x86_64-unknown-linux-gnu)`
       - `# Linux aarch64 バイナリ生成 (cross + aarch64-unknown-linux-gnu)`
       - `# Windows x86_64 .exe 生成 (cross + mingw)`
       - `# 3 つの cross-stable target を順次生成`
       - `# dist/ ディレクトリを削除 (cargo clean とは独立)`

  5. webif/Makefile を `git rm webif/Makefile` で削除 (履歴保持)。

  注意:
  - just は Makefile と違って `.PHONY` 不要、`$(VAR)` ではなく `{{var}}` 構文、
    各レシピ body の行は単一 shell で実行されるが行ごとに新 subshell ではない点を
    意識すること (Makefile の `@command || { echo ...; exit 1; }` パターンはそのまま
    動く)。
  - `mkdir -p {{dist_dir}}` を各 cross-release レシピ冒頭に置くことで、Makefile の
    `$(DIST_DIR)` order-only prereq を不要にする。
  - cross 実行時に Docker daemon が起動していなくても just / cross が即 fail する
    だけなので、daemon 確認はしない (Makefile と同じ方針、b7m-SUMMARY §「既知の運用上の注意」)。
  - `mkdir -p` / `cp` / `rm -rf` 等の標準 POSIX コマンドのみ使用、bashism は避ける
    (just default shell は `sh -cu`)。
  - 既存 dev レシピは 1 文字も変更しない (`build`, `run`, `test`, `fmt`, `clippy`, `clean`)。

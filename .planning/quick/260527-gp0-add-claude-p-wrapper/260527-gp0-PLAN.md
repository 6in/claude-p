  <action>
新規ファイル `webif/scripts/claude-p` を作成し `chmod +x` を付与する。bash スクリプト。

**ヘッダ / セットアップ:**
- Shebang `#!/usr/bin/env bash` + `set -euo pipefail`
- ファイル先頭にコメント（日本語）でスクリプトの目的・使い方・各サブコマンドの動作・`TURNS_DIR=./turns-${PORT}` という per-port 規約を 10〜15 行ほどで明記する
- `SCRIPT_DIR="$(cd "$(dirname "$0")" && pwd)"`、`WEBIF_DIR="$(cd "$SCRIPT_DIR/.." && pwd)"`
- `log()` 関数: `echo "[claude-p] $*" >&2`（stderr に出す）
- `usage()` 関数: 標準形・stdin 形・stop/status サブコマンドの使い方を stderr に書いて exit 1

**ツール検出:**
- `require_tool` ヘルパ（smoke.sh と同じ形）で `curl` の存在を必須チェック
- JSON エンコーダ検出: `JSON_ENCODER` 変数に `jq` か `python3` を入れる。両方無ければ exit 1（メッセージ「jq か python3 のどちらかが必要」）
- 単一の `json_encode_prompt` 関数を定義: 第1引数を `{"prompt": "..."}` の JSON 文字列に変換する。内部で `JSON_ENCODER` の値で分岐:
  - jq: `jq -n --arg p "$1" '{prompt: $p}'`
  - python3: `printf '%s' "$1" | python3 -c 'import sys, json; print(json.dumps({"prompt": sys.stdin.read()}))'`
- 単一の `json_get_field` 関数: 第1引数 JSON 文字列、第2引数フィールド名（status / turn_id / result / error）。同じ分岐:
  - jq: `echo "$1" | jq -r ".${2} // empty"`
  - python3: `echo "$1" | python3 -c "import sys, json; d=json.loads(sys.stdin.read()); print(d.get('${2}', ''))"`

**引数パース:**
- `$# -lt 2` で usage 出して exit 1
- 第1引数 `$1` を判定:
  - `stop` → `cmd_stop "$2"` を呼び exit
  - `status` → `cmd_status "$2"` を呼び exit
  - それ以外 → ポート番号として扱う。`[[ "$1" =~ ^[0-9]+$ ]]` でないなら usage 出して exit 1
- 標準形: `PORT="$1"`、`shift`、残りを prompt として扱う
- 残り引数が `-` 単独なら stdin から prompt を読む: `PROMPT="$(cat)"`
- それ以外は `PROMPT="$*"`（残り全引数をスペース結合）
- `PROMPT` が空文字なら usage 出して exit 1

**Per-port パス定数:**
- `BASE_URL="http://127.0.0.1:${PORT}"`
- `PID_FILE="/tmp/ht-webif-${PORT}.pid"`
- `LOG_FILE="/tmp/ht-webif-${PORT}.log"`
- `TURNS_DIR_PATH="${WEBIF_DIR}/turns-${PORT}"`

**Liveness probe 関数 `is_server_up()`:**
- `curl -s -o /dev/null --max-time 2 "${BASE_URL}/turns/0"` の exit code を返す
- 注: `/turns/0` は 400 を返すが、HTTP レスポンスが返れば curl は exit 0 を返すので「何らかの HTTP 応答」の検出として正しい（smoke.sh のコメント参照）

**Auto-start 関数 `ensure_server_running()`:**
- `is_server_up` が成功すれば `log "既存サーバを再利用: ${BASE_URL}"` で return 0
- PID ファイル存在 + プロセス生存 (`kill -0 $pid 2>/dev/null`) だが is_server_up が失敗 → 別ユーザのプロセスかもしれないので auto-kill せず、エラーログ + exit 1（「PID ${pid} は生存しているがポート ${PORT} に応答しません。手動で確認してください」）
- PID ファイル存在だがプロセス死亡 → ログ「古い PID ファイルを削除して再起動します」、PID ファイル削除
- spawn 処理:
  - `log "ht-webif を起動中... (port=${PORT}, log=${LOG_FILE})"`
  - `cd "$WEBIF_DIR"`
  - `nohup env PORT="${PORT}" TURNS_DIR="${TURNS_DIR_PATH}" cargo run --release >"${LOG_FILE}" 2>&1 &`
  - 直後に `local pid=$!`、`echo "$pid" > "${PID_FILE}"`、`disown` を実行
- Readiness 待機: 最大 60 回（1 秒間隔）`is_server_up` をリトライ、`kill -0 $pid` で早期死亡検知。失敗時は log 末尾 40 行を stderr に流し、PID をkill、PID ファイル削除して exit 1。5 秒ごとに進捗ログ
- 成功時: `log "サーバ起動完了 (pid=${pid})"`

**Submit + poll 関数 `submit_and_poll()`:**
- `local req=$(json_encode_prompt "$PROMPT")` — `set -e` で失敗即終了する
- `local resp` を `curl -s --max-time 30 -X POST "${BASE_URL}/prompt" -H 'Content-Type: application/json' --data-binary "$req"` で取得。curl 失敗時はエラーログ + exit 1
- `local turn_id=$(json_get_field "$resp" turn_id)`、空なら「turn_id が取れませんでした」とレスポンス本文を log して exit 1
- `log "ターン投入: turn_id=${turn_id}"`
- ポーリングループ:
  - `local max_polls=20`、`local interval=30`
  - `for i in $(seq 1 $max_polls); do`
    - `sleep $interval`
    - `local elapsed=$(( i * interval ))`
    - `local turn_resp=$(curl -s --max-time 10 "${BASE_URL}/turns/${turn_id}")` — curl 失敗時は警告ログのみで continue（一時的なネットワーク不調を許容）
    - `local status=$(json_get_field "$turn_resp" status)`
    - `case "$status" in`
      - `done|completed)` → result を取り出して stdout に出力、`log "完了 (経過 ${elapsed}s)"`、return 0
      - `failed|timeout)` → エラーログ + turn_resp 全体を stderr、return 1
      - `*)` → `log "polling... (経過 ${elapsed}s, status=${status:-unknown})"`
  - ループ抜けたら `log "ERROR: ポーリング上限 (${max_polls} 回 = $(( max_polls * interval ))s) を超えました"`、exit 1

**Stop サブコマンド `cmd_stop(port)`:**
- 引数バリデーション同様 `[[ "$1" =~ ^[0-9]+$ ]]`
- per-port 定数を再構築
- PID ファイル無し → `log "PID ファイルが見つかりません: ${PID_FILE}"`、exit 0（warning 扱い）
- PID 読み込み、`kill -0 $pid 2>/dev/null` で死亡確認 → 「プロセスは既に停止しています」+ PID ファイル削除 + exit 0
- `kill -TERM $pid`、最大 5 秒 1s sleep ループ待機、まだ生存していれば `kill -KILL $pid`
- PID ファイル削除
- `log "停止しました (pid=${pid})"`、exit 0

**Status サブコマンド `cmd_status(port)`:**
- per-port 定数を再構築
- 表示項目: PORT、PID file path、log file path、TURNS_DIR、サーバ応答 (`is_server_up` の結果)、PID（あれば）、プロセス生存（あれば `kill -0`）、ログ末尾 5 行（あれば）
- すべて stdout（パイプ可能にするため）。`log "..."` は使わず `printf` または `echo` で素直に
- exit code: サーバ応答 OK なら 0、それ以外 1

**Trap 設定:**
- スクリプト末尾でメインフロー前に `trap 'log "Ctrl-C を受信。サーバはバックグラウンドで稼働を継続します"; exit 130' INT TERM` を設定
- ※重要: トラップはサーバ kill しない。`task_specifics` の指示通り「server runs independently」を遵守

**メインフロー:**
- 関数定義群の後にメインフロー: 引数パース → サブコマンド分岐 or 標準フロー（`ensure_server_running` → `submit_and_poll`）

**最後に chmod:**
- ファイル書き終えたら別ステップで `chmod +x webif/scripts/claude-p` を実行

**禁止事項:**
- end-to-end 実行（cargo run / curl で本物のターン投入）は行わない。executor が消費する turn を増やさない
- `set -e` を切らない（無効化が必要な箇所は `|| true` で局所的に処理）
- `claude` バイナリの存在チェックはしない（ht-webif 本体が起動時に行うのでスクリプトでは不要、二重チェックは責務違反）

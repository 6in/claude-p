# Phase 260527-00i Plan 01: Make PORT and TURNS_DIR Configurable via Env Summary

PORT and TURNS_DIR are now configurable via environment variables, enabling multi-instance deployment on the same host.

## What Changed

### Task 1: config.rs + main.rs (commit c912fcb)

Added two new public functions to `webif/src/config.rs`:

- `load_port() -> anyhow::Result<u16>` — reads `PORT` env var, parses as u16, defaults to `8080`. Invalid values (e.g. `PORT=abc`) produce a clean anyhow error via `?` propagation from `main`, not a panic.
- `load_turns_dir() -> anyhow::Result<PathBuf>` — reads `TURNS_DIR` env var, defaults to `current_dir()?/turns`. The `current_dir()` fallible path is now handled with `with_context` rather than the bare `?` that was in main.rs.

Updated `webif/src/main.rs`:
- Import line updated to include `load_port` and `load_turns_dir`
- `let turns_dir = std::env::current_dir()?.join("turns")` replaced with `let turns_dir = load_turns_dir()?`
- `let addr = "127.0.0.1:8080"` / hard-coded bind replaced with `load_port()?` and `format!("127.0.0.1:{port}")`

The hardcoded `"127.0.0.1:8080"` string no longer appears in `main.rs`.

### Task 2: Documentation (commit 4a47a74)

- `webif/.env.example`: Added `# PORT=8080` and `# TURNS_DIR=./turns` comment blocks with priority notes. Existing `HT_MCP_PATH=ht-mcp` line preserved unconditionally.
- `webif/README.md`: Added `### 複数インスタンス運用` subsection under `## 起動` showing two-instance startup example. Added `PORT` and `TURNS_DIR` rows to the 環境変数 table.
- `webif/CLAUDE.md`: Updated `Single host` constraint bullet to note that multi-instance operation is possible by varying `PORT` and `TURNS_DIR`. HT-PROTOCOL §7 reference preserved.

- `PORT` unset → binds `127.0.0.1:8080` (same as before)
- `TURNS_DIR` unset → uses `CWD/turns` (same as before)

### Multi-Instance Smoke Test

```
PORT=18081 TURNS_DIR=$(mktemp -d) cargo run --release
```

- Server logged: `ターンディレクトリ: /tmp/tmp.2Cjy4j9g81` and `WebIF 起動: http://127.0.0.1:18081`
- `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:18081/turns/00000000-000000-000` → HTTP 404 (not 000 connection failure)
- Confirms both PORT and TURNS_DIR env vars are honoured at runtime.

# Requirements: ht-webif

**Defined:** 2026-05-23
**Core Value:** `-p` を避けつつ curl で Claude を実行できる（サブスクリプション課金を維持）

## v1 Requirements

「**webif/ を本格的な開発リポジトリとして整える**」マイルストーン。アプリ本体の機能（WEBIF-*）は PROJECT.md の Validated に既にあり、ここでは"開発リポジトリとしての体裁・運用基盤"を確立する。

### Repository（リポジトリ体裁）

- [x] **REPO-01**: README.md を整備する（プロジェクト概要、ビルド・起動方法、API 例、依存条件）
- [x] **REPO-02**: LICENSE ファイルを追加する（MIT or Apache-2.0 のいずれか）
- [x] **REPO-03**: `.gitignore` を整備する（`target/`、`turns/`、`.env`、IDE 関連、OS 生成物）
- [x] **REPO-04**: `webif/Cargo.toml` のメタデータを充実させる（`description`、`repository`、`license`、`authors`、`readme`、`edition` 等）

### Code Structure（コード構造）

- [x] **CODE-01**: `webif/src/main.rs`（~500行）をモジュール分割する（`mcp_client`、`worker`、`turn`、`handlers`、`config` 等を `lib.rs` 配下に切り出し、`main.rs` は薄くする）
- [x] **CODE-02**: モジュール分割後も既存の HTTP API（`/prompt`、`/turns/{id}`、`/command`、`/restart`）が同じ振る舞いで動くこと

### Testing（テスト）

- [x] **TEST-01**: 純粋関数（turn_id 生成・パス組み立て・prompt body 組み立て等）の単体テスト
- [x] **TEST-02**: MCP クライアントの JSON-RPC リクエスト/レスポンス組み立ての単体テスト
- [x] **TEST-03**: HTTP ハンドラの統合テスト（ht-mcp をモック / スタブ化、`/turns/{id}` のパストラバーサル拒否確認も含む）

### Tooling（開発ツール）

- [x] **TOOL-01**: `justfile` または `Makefile` で開発コマンドを集約する（`build`、`run`、`test`、`fmt`、`clippy`、`clean`）
- [x] **TOOL-02**: `.github/workflows/ci.yml` を追加して、push/PR で `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test` を自動実行

## v2 Requirements

v1 完了後に取り組む。今のロードマップには含めない。

### Operations

- **OPS-01**: `turns/` ディレクトリのローテーション/アーカイブ運用（hot ディレクトリと archive を分離、サイズ/日数で自動移送）
- **OPS-02**: 構造化ロギング（`tracing` crate）と最低限の観測性（リクエスト ID、ターン ID、所要時間）

### Security

- **SEC-01**: HTTP エンドポイントの認証（最低限 bearer token、ローカル外公開時の前提）

### Scaling

- **SCALE-01**: 並列ワーカー（複数 ht-mcp / claude セッション）。turnId に worker ID を含める設計準備は済（HT-PROTOCOL §3）

### Deployment

- **DEPLOY-01**: Docker 化（claude を含むコンテナ + 認証情報のマウント方式の確立）

## Out of Scope

明示的に範囲外。再提案を防ぐために理由を残す。

| Feature | Reason |
|---------|--------|
| `claude -p` 利用 | Core Value に反する（サブスクリプション課金が変わるとユーザが判断）。本 WebIF の存在意義そのもの |
| MCP プロトコル拡張・改造 | ht-mcp は外部依存。本プロジェクトは MCP クライアント実装に留める |
| claude TUI の機能拡張 | Claude Code は別プロジェクト。本 WebIF は薄いブリッジに徹する |
| マルチホスト分散 | 単一ホスト前提。SCALE-01 を超えて必要になったら別途検討 |
| GUI / Web フロントエンド | HTTP/JSON API までが本プロジェクトの責務。UI は呼び出し側で実装 |

パストラバーサル防御の所在 (webif/src/http.rs:89-92):
```rust
async fn turn_handler(
    State(state): State<Arc<AppState>>,
    AxumPath(turn_id): AxumPath<String>,
) -> Result<Json<Value>, (StatusCode, String)> {
    // パストラバーサル防止: turn_id は数字とハイフンのみ
    if turn_id.is_empty() || !turn_id.chars().all(|c| c.is_ascii_digit() || c == '-') {
        return Err((StatusCode::BAD_REQUEST, "不正な turn_id".to_string()));
    }
```

**axum 0.8 のパスデコード挙動（B1 fix の前提）:**
- ハンドラは `AxumPath(turn_id): AxumPath<String>` を使用（`webif/src/http.rs:87`）
- axum 0.8 の Path extractor は **percent-encoded スラッシュ `%2F` を path 区切りとして扱わない** — `/turns/..%2Fetc%2Fpasswd` は `/turns/{turn_id}` にマッチし、`turn_id = "../etc/passwd"` がそのままハンドラに届く
- このため whitelist `c.is_ascii_digit() || c == '-'` が `.` と `/` を弾き、400 を返す
- つまり「`..%2Fetc%2Fpasswd` ではマッチしないかも」という懸念は不要 — マッチして 400 を返すのが確定挙動
- ベアな `/turns/../etc/passwd` はルーター段階で `/etc/passwd` に正規化されてしまうため、テストでは **必ず `%2F` エンコード版を使う**

FakeMcp の所在（Plan 03-03 完了後）:
- `use crate::mcp::tests::FakeMcp;`
- `FakeMcp::new()` で空のインスタンス取得可能

Worker<FakeMcp> の組み立て上の難点:
- `Worker::new(ht_mcp_path)` は `impl Worker<McpClient>` 専用なので使えない
- `Worker<FakeMcp>` は test 側から構造体を直接 `Worker { client: FakeMcp::new(), session_id, ht_mcp_path }` のように組み立てる必要がある
- ただし `Worker` のフィールドは pub ではない（`client: M` は private、`session_id: pub`、`ht_mcp_path: private`）
- 対応: `webif/src/worker.rs` の `Worker` に `#[cfg(test)] pub(crate) fn from_parts(client: M, session_id: String, ht_mcp_path: String) -> Self` を追加する必要がある（test 用 ctor、D-25 のテスト時可視性方針に従う）
